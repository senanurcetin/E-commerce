# NEXUS Commerce — reproducible native Power BI PBIP pipeline

## Registered NEXUS brand assets

The PBIP generator automatically copies the original owner-approved
`branding/nexus_official_transparent.png` into the report's
`StaticResources/RegisteredResources` folder, registers a native image visual
on **each of the six pages**, packages the dark navy/cyan/purple theme and
points `definition/report.json` at that registered custom theme. The PNG asset
matches the user's original Google Drive file; no replacement generated logo
or unsecured remote image URL is used.

The report is still a **PBIP source/development project**, not a verified
Power BI Desktop export. Actual theme/visual rendering, refresh, DAX and
licensing acceptance must be checked in Power BI Desktop. Missing E-Commerce
and Greenweez finance source marts remain blank, and Greenweez Sheets
observations are not certified transaction totals.


## Deliverable

This repository can generate a NEW native Power BI Desktop **.pbip** project
with **PBIR report definitions** and a **TMDL semantic model**, rather than
requiring an unknown old PBIX. It uses Microsoft-supported folder structures,
but Power BI Desktop is required to inspect/render/refresh the result.

**No simulated transactions are added.** The pipeline reads source-qualified
aggregate-only JSON produced by the independently validated NEXUS
E-Commerce/Greenweez/Commerce Lab source adapters.

Read from:
- target/ecommerce_bridge/snapshot.json
- target/greenweez_bridge/snapshot.json
- target/greenweez_bridge/google_sheets_observed.json
- target/google_measurement/lab_ga4_events.json
- the eight-source workspace evidence registry

A missing source yields a CSV **header only**, not a synthetic order or fake
revenue. A missing source must not be interpreted as zero business activity.

## Build from the E-Commerce repository root (Windows)

~~~cmd
cd /d C:\Users\MONSTER\E-commerce
python -m pip install -r dashboard\requirements.txt
python -m scripts.nexus_workspace status
python -m scripts.build_powerbi
~~~

Open this locally generated file in Power BI Desktop:

~~~text
C:\Users\MONSTER\E-commerce\target\powerbi\project\NEXUS_Commerce.pbip
~~~

The project contains:
- \`NEXUS_Commerce.SemanticModel/definition/\` with a TMDL model and
  seven fully source-isolated import tables.
- \`NEXUS_Commerce.Report/definition/\` with six source-specific PBIR report
  pages and ready-defined native card / line / column / table visuals.
- \`target/powerbi/marts/\` with seven **local gitignored CSV sources**.
- \`target/powerbi/build_evidence.json\` capturing row counts, source
  provenance, page list, and open acceptance gates.

Pages: Source Assurance, Historical E-Commerce, E-Commerce Sessions,
Greenweez Finance, Greenweez Source Quality, Commerce Lab Tests.

The \`pDataFolder\` **Power Query parameter** references the absolute local
folder of these aggregate CSVs. Rebuild on a different computer to update
that path, or change the parameter in Power BI Desktop.

Data provenance:
- **E-Commerce:** order and web session marts, source-specific dates.
- **Greenweez Finance:** separate dbt finance mart; never combined with
  historical E-Commerce sales.
- **Greenweez Source Quality:** original 2021 Google Sheets aggregate
  observations, with 5,314 blank turnover values tracked separately;
  incomplete totals are not confirmed company sales.
- **Commerce Lab:** GA4 \`lab_*\` test events, not paid purchases.
- **Source Assurance:** import status/provenance rather than financial totals.

The semantic model intentionally defines **no cross-merchant relationships**,
no inferred campaign attribution, no blended cross-business ROAS/CAC, and no
currency conversions. Even technically validated external finance data are
not claimed source-accounted.

## NEXUS visual theme

After opening the generated PBIP, select **View → Themes → Browse for themes**
and import:
\`powerbi/themes/nexus-commerce.json\`

This is the same navy/cyan/purple design family as the Streamlit dashboard.
Actual Power BI Desktop render and visual background overrides remain
independent acceptance gates.

## Refresh / repeat

Run \`python -m scripts.build_powerbi\` to re-export only currently
available validated source snapshots and regenerate PBIP metadata. Reload
or refresh Power BI Desktop. The generator does **not** call Google APIs or
obtain credentials in the background. GA4 event data first requires a
separate authorized Data API export via
\`python -m scripts.lab_ga4_events\`.

## CI and final acceptance

~~~cmd
python -m unittest discover -s tests -p test_build_powerbi.py -v
python -m scripts.powerbi_acceptance --output target\powerbi\desktop_qa.json
~~~

CI validates structure, no invented revenue, source isolation, required
PBIR/TMDL files, semantic measure scopes, and repeatability.

**Known limitation: the autogenerated PBIP has not been confirmed openable
and visually correct by Power BI Desktop until the owner actually opens it.**
PBIR is a supported text format, but static tests are not proof of rendering.
Power BI Desktop is also required to save the authored PBIP as a packaged
PBIX; there is no supported pure-Python PBIX binary compiler. Final
acceptance remains HOLD until actual Desktop refresh, every visual rendered,
theme imported, and business amounts independently reconciled.

Do not commit the generated \`target/powerbi/\` folder to GitHub. For sharing
a report, publish only an audited PBIX/PBIP with appropriately governed
data/security. Do not expose raw orders or paid campaign identifiers.
