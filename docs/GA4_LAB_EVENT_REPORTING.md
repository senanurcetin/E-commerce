This is a **ready-to-authorize implementation**, not a claim that an owned Commerce Lab GA4 property or Analytics Data API connection is already active.

The site has **no owned GA4 Measurement ID configured as of this work**. Creating a property requires the user's Google Analytics Admin access; it cannot be inferred from a previously existing stream. Preserve both ToyStore and portfolio GA4 configurations.

## Step 1 — Register a new property and web stream

In [Google Analytics](https://analytics.google.com/), use **Admin → Create → Property**. Give it the name `NEXUS Commerce Lab`; in the property create a **Web data stream** using the exact URL `https://nexus-commerce-lab.vercel.app/`, with the name `Commerce Lab Web`.

Copy these **different** identifiers from the newly created property:

- **Measurement ID:** `G-XXXXXXXXXX` — public, injected into storefront HTML build.
- **GA4 Property ID:** numeric — required by the GA4 Data API collector.
- **Stream ID:** numeric but is **not** the Property ID; never substitute it.

Neither code nor this document should contain a real OAuth access token, ADC file, account password or service-account JSON.

## Step 2 — Attach ONLY the new ID to Vercel

In the authorized Vercel project **nexus-commerce-lab**, add environment variable:

- Name: `NEXUS_GA4_MEASUREMENT_ID`
- Value: new **Commerce Lab** `G-...` Measurement ID
- Targets: production (optionally preview when separately reviewed)

Deploy the current `main` build. The static public `/config.js` must show the correct new public ID, never the ToyStore ID. Vercel includes deployment protection on previews; do not weaken access to preview deployments.

Consent is scoped to the Measurement ID. Consent to a previous GA4 property is not transferred to a new ID. Analytics runs only after opt-in; advertisements/ad-personalization storage remain denied. Browser storage being unavailable does not authorize tracking.

## Step 3 — Real visitor acceptance

Open the public site in a clean browser profile.

1. Before consent, verify Chrome Network shows no request to `gtag/js` and no GA4 events.
2. Click **Allow analytics**; this explicitly enables the optional Google tag.
3. Interact with catalog and cart and complete the **no-payment test checkout**.
4. Verify `lab_page_view`, `lab_view_item`, `lab_add_to_cart`, `lab_remove_from_cart` and `lab_checkout_completed` in the correct new GA4 property's Realtime/event reports, as applicable. DebugView may require debug mode.
5. Confirm there is **no** GA4 `purchase` or `value` event generated by the Lab. Test checkout totals in the UI are not revenue.
6. Reject consent and ensure no new custom events are transmitted after revocation. A record already transmitted cannot be retroactively un-sent.

An absence of events in the first minutes may be due to reporting latency, deployment config, browser protection or incorrect property access. Never replace an unavailable live metric with a demo number.

## Step 4 — Read-only aggregated data collector (optional, requires Google permission)

The collector requires a **numeric GA4 Property ID** and Google Application Default Credentials with Analytics read access. Merely having a public `G-...` Measurement ID does *not* grant permission to query the property. When authorized:

~~~cmd
cd /d C:\Users\MONSTER\E-commerce
python -m pip install "google-auth[requests]>=2,<3"
set GA4_LAB_PROPERTY_ID=123456789
python -m scripts.lab_ga4_events --start 2026-10-16 --end 2026-10-16
python -m streamlit run dashboard\google_marketing_app.py
~~~

Replace the numerical example with the **new Commerce Lab Property ID**. Authentication must already be configured by the property owner via read-only ADC; do not commit credential files. The collector filters by exact hostname `nexus-commerce-lab.vercel.app` and five allowlisted custom event names. It exports only daily event counts, without visitors, device IDs, item IDs, addresses or purchase values.

The collector fails closed on invalid API schema, negative/partial data, unexpected host/event labels or duplicate date/event grains, and does not create a fallback synthetic snapshot if no property is accessible.

### Dashboard interpretation

The **Commerce Lab · Test Events** tab shows daily occurrences of:
`lab_page_view`, `lab_view_item`, `lab_add_to_cart`, `lab_remove_from_cart`, `lab_checkout_completed`.

These are **counts of recorded events**, not distinct users, sessions, fulfilled orders, conversions verified by payments, or income. A visitor can add many cart items. A completed lab checkout triggers no commercial transaction. If the authenticated GA4 API returns no matching event rows, the UI must state **no observed events**, not fabricate zeros with a misleading claim.

GA4 sample/fixture data used in offline CI tests are never treated as real production measurements. The earlier GA4 acquisition mart `ga4_channel_daily.csv` is intentionally a separate data product.
